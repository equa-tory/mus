# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Running the server

```bash
pip install -r requirements.txt
MUSIC_DIR=/path/to/music uvicorn app:app --host 0.0.0.0 --port 8000
```

Configuration is entirely via environment variables:
- `MUSIC_DIR` — path to the music folder (default: `./music`)
- `DATA_DIR` — where the SQLite database and extracted album art are stored (default: `./data`)
- `PASSWORD` — optional; read from the environment or a git-ignored `.env` next to `app.py` (`_load_dotenv`, real env vars win). Unset/empty = no auth at all. Set = single shared password, no usernames (see Auth below).
- `LISTEN_ONLY` — optional (`true`/`1`/`yes`/`on`, also via `.env`); only effective with a `PASSWORD`. Guests can only listen along (see Guest mode below).
- `REQUIRE_LOGIN` — optional (`true`/`1`/`yes`/`on`, also via `.env`); only effective with a `PASSWORD` (otherwise ignored with a warning). Hides the whole app behind `static/login.html` (see Auth below).
- `DOWNLOAD_DIR` — where the YouTube downloader saves songs (default `/mnt/videos/Loop`; flat `.m4a` files, outside `MUSIC_DIR` on purpose, so the scanner never sees them). See Downloader below.
- `BACKUP_DIR` (default `/mnt/backup/mus`, empty = off), `BACKUP_EVERY_HOURS` (default `48`, `0` = manual only), `BACKUP_KEEP` (default `1`) — automatic database backups (see Backups below).

## Architecture

This is a small project: a FastAPI backend (`app.py`), the YouTube-downloader logic (`ytdl.py`, routes live in `app.py`) and a single-file vanilla-JS SPA (`static/index.html`). There is no build step or bundler; the only tests are `test_ytdl.py` (`venv/bin/python -m unittest test_ytdl`) for the downloader.

### Backend (`app.py`)

- **FastAPI** serves all API routes under `/api/*`; the static directory is mounted last so it only handles non-API paths.
- **SQLite** (WAL mode, `DATA_DIR/library.db`) stores tracks, playlists, playlist membership, and play history. The `db()` helper opens a new connection per call — connections are not shared across requests.
- **Scanning** (`POST /api/scan`) runs in a background `threading.Thread`. Progress is tracked in the module-level `SCAN` dict and polled via `GET /api/scan/status`. Unchanged files (same mtime + size) are skipped for speed. Removed files are detected by comparing `last_scan` timestamps.
- **Metadata** is read with `mutagen`. Cover art is extracted and saved to `DATA_DIR/art/<id>.jpg|.png`; the `has_art` / `art_ext` columns track what was found.
- **Audio streaming** (`GET /api/stream/{id}`) is a plain `FileResponse` (Starlette handles Range), with two exceptions. 0-byte files return 422 (they're flagged `broken` in `/api/tracks`). Apple Lossless (ALAC) `.m4a` files, which Chrome/Firefox can't decode, are transcoded live: the response is a *virtual* 16-bit PCM WAV whose exact length is computed from the metadata (`_alac_info`), with Range parsed by hand and each request running `ffmpeg -ss <sample offset>` piped out (`_pcm_stream`; killed when the client disconnects). Nothing is cached or written to disk. Needs `ffmpeg` on PATH; without it ALAC falls back to the raw file and the client skips it.
- **Shutdown**: `/api/sync/events` streams never end on their own and uvicorn waits for open connections, so without `--timeout-graceful-shutdown` a restart hung until systemd's 90 s SIGKILL (reproduced: one open stream, SIGTERM → >100 s). `mus.service` passes `--timeout-graceful-shutdown 3` (+ `TimeoutStopSec=15`); keep the flag in any other way of launching the server.
- **Cross-device sync** (`GET /api/sync/events`, `POST /api/sync/{state,cmd,claim,release,leave}`) is an SSE fan-out where the server is the sole authority over which connected client owns audio (`_SYNC_OUTPUT`). `GET /api/sync/events?cid=&want=` registers a client and grants it output only if none is currently assigned; `POST /api/sync/state` is rejected unless it comes from the current output. This split — one publisher of truth, everyone else sends intent — is what stops a client from taking over or corrupting playback just by opening the page.

- **Auth** (only when `PASSWORD` is set): `POST /api/login` sets an HttpOnly cookie `mus_auth` = HMAC of the password (so changing it logs everyone out; 5 bad tries per IP → 429 for 5 min), `GET /api/auth` reports `{required, authed, listenOnly}`. Reads (tracks, art, stream, history, playlists GET, scan status, the sync feed) stay open; every mutating route has `dependencies=OWNER` (`owner_only` → 401), including all of `/api/sync/{state,cmd,claim,release,leave}` — authority comes from the cookie, never from knowing a `cid`. With `REQUIRE_LOGIN` the app-wide `login_gate` dependency also 401s every `/api/*` route except `/api/{auth,login,logout}` for visitors without the cookie, and the `/` and `/index.html` routes (declared before the static mount) serve `login.html` instead of the SPA, so no guest mode exists in that setup. Unauthenticated `sync/events` connections are registered in `_SYNC_LISTENERS`: they receive `hello`/`role`/`state` (never `cmd`), are not counted in `peers` and can never be granted output.

- **Backups**: a daemon thread (`_backup_loop`) snapshots `library.db` into `BACKUP_DIR` as `mus-YYYYmmdd-HHMMSS.db` via sqlite's online backup API whenever the newest one is older than `BACKUP_EVERY_HOURS` (so restarts don't skip or repeat), then prunes to `BACKUP_KEEP`; errors (e.g. drive not mounted) land in `BACKUP["error"]` and it retries hourly. Only names matching `BACKUP_RE` are ever listed, served or deleted. Owner-only routes: `GET/POST /api/backups`, `GET /api/backups/{name}`, `POST /api/backups/{name}/restore`, `POST /api/backups/upload` (raw body, 1 GB cap). Restore validates the file (`quick_check` + required tables → 400), refuses during a scan (409), saves the current DB to `DATA_DIR/pre-restore.db`, then copies over the live DB. Art isn't backed up (a scan rebuilds it).

- **Settings / following** live in the `meta` table (so they sync across devices and are included in backups): `GET /api/settings` (open) returns `{authorSep, following}`; `PUT /api/settings` (owner) sets `authorSep` (default `/`, ≤20 chars, stripped); `POST /api/authors/follow {key, follow}` (owner) adds/removes a lower-cased author key. Authors themselves aren't stored — the client derives them from `tracks.artist`.

- **Downloader** (`ytdl.py`, routes `/api/dl/*` in `app.py`, all `dependencies=OWNER`; UI = `downloadModal()` opened from ⚙ Settings → Download music): a port of Lasso's audio mode and HomeFlix's downloader. Flow: saved playlist link (`dl_sources`, created lazily by `_conn()` so a restored old backup still works) → `fetch_playlist()` (`yt-dlp --flat-playlist`, cached in `entries_json`) → `classify()` → ticked ids → `start_job()` (one job at a time, in-memory `JOB` dict, daemon thread, yt-dlp via `Popen`). Things that aren't obvious:
  - **Files are flat `<video title>.m4a`** in `DOWNLOAD_DIR` (not `MUSIC_DIR`); `build_cmd` uses `-x --audio-format m4a` (AAC is copied, anything else converted) + `--embed-thumbnail --convert-thumbnails jpg` + `--embed-metadata`, the shared Lasso archive `_yt_archive_<md5(url)[:8]>.txt`, `web_embedded,default` player client and an explicit `--js-runtimes deno:<path>`.
  - **Tags come from `derive_tags()`, applied after the download by `retag()` (mutagen)**: YouTube Music fields (`track`/`artists`/`album`, artists de-duplicated and joined with ` / `) when present, else an `Artist - Title` video title **only if the channel confirms which half is the artist** (otherwise the channel, minus "- Topic"/VEVO/Official, is the artist and the title stays whole — Lasso's rule), album = YouTube album or the title. yt-dlp hands the fields over via `--print-to-file after_move:'%(id)s\t%(filepath)s\t%(.{...})j'`, which is also the success marker (exit codes mean little with `--ignore-errors`).
  - **Status is by name** (`name_key`: NFKC + casefold + strip non-alphanumerics) against files in the download folder, the library's `tracks` (exact: title, "artist title", file name; then `fuzzy_library()`: a library title *contained in* the YouTube title or the reverse counts as `library` if one of the track's artists is also in the title/channel, else as `similar` when the title is 4+ chars — real YouTube titles ("【MV】Song / Artist") almost never equal the tag title, exact-only matching found 267 of 1059 and fuzzy ~515) and Lasso's archive. Precedence: unavailable > downloaded > library > skipped > similar > archived > new (your own skip beats a weak guess). Results are memoised per library signature (`_FUZZY`).
  - **Download folder** = meta key `dl_dir` (set in ⚙ Settings → Download music via `PUT /api/dl/dir`, validated absolute + writable, `""` resets) else `DOWNLOAD_DIR`; it also decides where the Lasso archive lives, so changing it means earlier downloads are no longer recognised. The flat playlist listing can show a *translated* title while the file gets the original-language one, so such songs show as "downloaded" (archive) rather than "in folder" — that's expected.
  - **Cookies** are pasted (Netscape or `Cookie:` header) and stored 0600 in `data/ytdl/cookies.txt` (git-ignored, never sent back). YouTube invalidates them silently and yt-dlp then downloads logged out, so `check_cookies()` probes the Watch Later list on a temp copy (True/False/None; `data/ytdl/cookie_check.json`, void when the cookie file changes); `start_job` refuses without cookies/expired, `_run_job_inner` re-checks and kills yt-dlp the moment it prints "cookies are no longer valid".
  - **JS runtime** must be new enough (`_MIN_RUNTIME`: Deno ≥ 2.3, Bun ≥ 1.2.11, Node ≥ 22; an older one is silently ignored by yt-dlp and every download dies at the challenge step). `install.sh` installs Deno into `./.deno` (git-ignored); `js_runtime()` finds it.
  - Bulk skip/un-skip only accepts ids that are in the cached list; "skipped" is a DB row (`dl_skipped`), never an edit of the archive. Disk: `disk_info()`/`free_space()`, refuses below 1 GiB, size estimate = duration × 20 KB/s.

- **Pull from another computer** (`macpull.py`, routes `/api/pull*` in `app.py`, all `dependencies=OWNER`; UI = `pullSection()` in ⚙ Settings): copies songs that aren't in `MUSIC_DIR` yet from `user@ip:/full/path` (meta key `pull_src`, default `macpull.DEFAULT_SOURCE` = the Mac's Apple Music folder, which has the same `Artist/Album/file` layout as `MUSIC_DIR`) over ssh, then rescans (`_start_scan`). Flow: `rsync --list-only` (audio extensions only) → drop paths already present → `rsync --files-from` into `DATA_DIR/pull` staging → move into place → scan. Non-obvious: (1) **comparison is by NFC-normalised path** — macOS stores names decomposed (NFD), so plain `rsync --ignore-existing` re-copied 126 of 165 "new" songs; new files are stored NFC and reuse an existing folder whose name only differs in normalisation. (2) Needs **key-based ssh** (`BatchMode=yes`, `accept-new` host key) from the service user, plus rsync/ssh installed (`install.sh` does). (3) `-s`/`--protect-args` must NOT be passed (the Mac's rsync 2.6.9 rejects it); local rsync ≥3.2.4 escapes spaces itself, so pass the path raw. (4) `-8` keeps non-ASCII names unescaped under systemd's C locale. (5) Never deletes or overwrites anything, either side; names over 255 bytes are skipped (ext4). (6) One job at a time in the in-memory `JOB` dict, cancellable. Tests: `venv/bin/python -m unittest test_macpull`.

### Frontend (`static/index.html`)

All JS lives in a single IIFE inside the HTML file. State is in a single `S` object. Key design choices:

- **Two persistent `<audio>` elements** (`aud[0]` and `aud[1]`, index toggled with `ai^=1`) are the core trick that enables crossfading and avoids autoplay-policy re-blocking on every track change.
- **Crossfade** is implemented with `requestAnimationFrame` volume ramps (`fade()`) applied to the outgoing and incoming elements simultaneously.
- **Playback state** (queue, position, volume, shuffle, repeat, crossfade duration) is persisted to `localStorage` and restored on boot so playback resumes where the user left off.
- **Smart playlists** are evaluated client-side in `smartIds()` against the in-memory `S.byId` map.
- **Cross-device sync/remote control**: the server assigns each connected browser a `role` of `output` (owns the `<audio>` elements, publishes full state via `pushState()`) or `controller` (mirrors state, sends intent via `sendCmd()`); `S.role` is never chosen client-side, only requested (`rolePref` in `localStorage`, sent as `want=` on connect) and confirmed by the server's `hello`/`role` SSE messages. Controllers never publish state — only the output does, and the server enforces this — so a newly opened tab can't clobber a device that's already playing; taking over audio requires an explicit tap (`claimOutput()`/`releaseOutput()`, `POST /api/sync/{claim,release}`). `applyState()` treats the published track `id` as authoritative and repairs `pos` to agree with it, which is what keeps the displayed title and the loaded audio from diverging. `applyCmd()` is where the output executes a controller's command (play/pause/seek/volume/crossfade/shuffle/repeat/sleep/queue edits) by calling the same local functions its own UI uses, so results flow back out through the normal `pushState()` path.
- **Playback errors**: each `<audio>` has an `error` listener (`onAudioError`) that flags the track (`t.failed`), toasts, and skips to the next one (gives up after 5 in a row).
- **Mini bar (>640px)**: centre column stacks the transport buttons over a seek slider (`#barSeek`, shares `bindSeek()` with the sheet's slider); right side has like / add-to-playlist picker / sleep popover / output-role toggle. Phones keep the thin progress line.
- **Desktop side-panel mode**: `body.side-mode` (toggle `#dockBtn`, saved as `localStorage.sheetMode`; on by default and opened on load on wide screens, only an explicit `"full"` opts out) docks the now-playing sheet to the right, resizable via `#sideGrip` (width in `localStorage.sideW`). All its CSS is gated on `(min-width:900px) and (hover:hover)`. `#sideQueue` shows up to 25 history tracks (from `/api/history`), now playing, and up next via `fillQueue(body,true)`.
- **Guest mode** (`S.guest` = password required and not logged in; `body.guest`): `S.role` is pinned to `"output"` so the local player works unchanged, but `pushState/syncState/sendCmd/claim/release/leave` are no-ops and `countPlay` doesn't hit the server; writes (like, playlists, scan) call `denyGuest()` which toasts instead. The `#live` corner panel shows the owner's published state (`S.live`, via `guestSyncMsg`); on the first `hello` the guest auto-follows (`startFollow` → `followApply`): loads the owner's track/queue, mirrors play/pause and re-seeks when drift exceeds 1.5 s. While `S.follow`, local transport/seek/queue actions are blocked by `followLocked()` and auto-advance is disabled; **Stop** (`stopFollow`) hands control back locally. With `LISTEN_ONLY` (`S.listenOnly`, `body.listen-only`) the guest follows from the first `hello` even if the owner isn't playing yet, the Stop button is hidden and `stopFollow` is a no-op, so `followLocked()` blocks every manual action for good (UI-only: `/api/stream` stays open).
- **Phone layout (≤640px)**: `header` (which now also contains `nav#tabs`) becomes a fixed bottom dock (`--dock-h`, lifted by `--kb` on iOS via `visualViewport`; Chromium uses `interactive-widget=resizes-content`); everything that sits above the bottom adds `var(--dock-h)`. Search is the round `#searchBtn`; tapping adds `header.searching` (input expands, other items hide) and blur folds it back. `#player` is `pointer-events:none` (its box spans the dock) with its children re-enabled. The mini bar hides `#barRight`/shuffle/repeat on phone. `.view-bar` (Shuffle play) is `position:sticky` so it stays visible while scrolling. The ⚙ button (`#settingsBtn`) opens the backups modal (`backupsModal`); on phone Scan and Log in/out are hidden from the dock and shown at the top of that modal instead (`accountButtons`), and guests get a minimal modal with just Log in. On desktop the ⚙ is hidden for guests.
- **Authors**: tab `authors` (index) → view `author` (`S.openAuthor` = key). `authors()` builds a cached Map by splitting each track's `artist` on `S.settings.authorSep` and grouping case-insensitively (`authorKey`); the cache (`S._authors`) is reset when tracks or the separator change. Followed authors (`S.settings.following`, toggled with ★ via `toggleFollow`) are listed first under "Following". The separator is edited in the ⚙ Settings modal. Inside an author, `viewIds()` returns that author's tracks, so Shuffle play and search work like any other list; on the index, Shuffle plays the followed authors' tracks (or everything shown if none are followed).
- **Phone shuffle button**: on ≤640px the in-list Shuffle button is hidden and `#fab` (floating, bottom-right above the mini bar/dock; `body.has-fab`/`has-player`) replaces it; `setFab()` sets its action per view and `render()` clears it first.
- Rendering is done by rebuilding the DOM directly (no virtual DOM); `content-visibility: auto` is used on rows for scroll performance.
- The app is installable as a PWA (`static/manifest.json` + icons); there's no service worker, so it requires network connectivity.
